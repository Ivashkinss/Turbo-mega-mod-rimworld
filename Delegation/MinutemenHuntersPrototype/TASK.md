# MinutemenHuntersPrototype — большой отдельный играбельный кандидат

Это НОВАЯ задача, не продолжение теста клиники. Ориентир объёма — около1–2часов содержательной разработки: сначала законченный минимальный игровой цикл, затем проверки и доработка. Не тратить время искусственно и не завершать работу одним планом/инвентаризацией. Codex вернётся после лимита, независимо проверит и интегрирует кандидат. Статус running при старте, done только когда создан REPORT; если часть не готова, честно отметить её.

## Изоляция и вход
Запись ТОЛЬКО Tools/Build/GeminiMinutemenHuntersPrototype/ и Tools/Build/GeminiWorkerState/MinutemenHuntersPrototype.json. Читать immutable Tools/Build/MinutemenHuntersSnapshot/ (проверить SNAPSHOT.json), корневые Source/Defs/Documentation/Tools/build_assembly.ps1, игровые ../../Data/{Core,Royalty,Ideology,Biotech,Anomaly,Odyssey}/Defs и installed reference/provider DLL можно. Реальные исходники Hospital находятся Components/Hospital/UpstreamSource/Hospital/. Корень Source/Defs/Languages/Assemblies/Components/пользовательскую игру/конфиги/сохранения/Git/QUEUE не менять. Игру/GUI/сеть не запускать. Assembly-CSharp читать только metadata/Cecil, не исполнять. C# компилятор можно запускать; использовать уже доступные локальные зависимости, ничего не устанавливать.

## Концепция и граница
Будущий общий мир Fallout × «Сверхъестественное». Первой фракцией делаем **«Минитмены и охотники»**: гражданское ополчение поселений и охотники на нечисть, помощь поселениям, полевые медики, радиосвязь, архивы оберегов. Равноправное смешение обоих сеттингов, а не простой рескин рейдеров. Имена/тексты авторские. Никаких эротических услуг, работ за сексуальный выкуп или изменений гостиничных договоров. Происшествия гостиницы, карательные рейды/обман и большой канонический сюжет с пользователем отложены; здесь отдельный небольшой прототип фракционной помощи, не финальный сюжет и не автоматические гостиничные нападения.

## Обязательный результат: рабочий кандидат, не только дизайн
### 1. Фракция и пешки
- Namespaced DefNames TMM_Hunters* / TMM_MinutemenHunters*. Одна человеческая преимущественно дружественная фракция, три понятные роли пешек: ополченец, охотник, полевой медик. Использовать существующие ванильные расы/одежду/оружие/ресурсы по настоящим defName; не требовать несуществующих лазерных мушкетов/демонов/машин. Контент без обязательного DLC, DLC-расширения строго условные, если вообще нужны. Сложное оружие/силовая броня не входят в этот этап.
- Нормальные combat/peaceful/trader/settlement PawnGroupMaker по доступным API, без абсолютных packageId-проверок на будущие фракции, без автоматического VIP/дохода/выкупа. Умеренное вооружение и численность. Новые люди не должны ломать существующий поиск допустимых фракций гостиницы/опта/клиники.
- Появление в новом мире и безопасное предложение/добавление в старом мире: не создавать дубликаты при загрузке, не перезаписывать отношения уже существующей фракции и не регенерировать чужие поселения. Если добавление на старый мир слишком рискованно, реализовать явный одноразовый debug/quest entry point для Codex и честно ограничить автоматическую часть новыми мирами, а не делать недоказанную миграцию.

### 2. Узнаваемая база
- Кандидат собственного поселения/аванпоста примерно45×45: центральная радиорубка, жилой блок, медпункт, склад и архив, ограда/входы и обзорные позиции. План должен отличаться от обычного vanilla scatter settlement. Реальные проходимые двери/пути, внутренние крыши/температура/кровати/столы; не запечатывать карту и не рисовать декорации вместо зданий.
- Использовать корректный native MapGenerator/GenStep/BaseGen API, только для этой фракции или её квестового site. Не менять генерацию чужих поселений. Размер ограничен, без тысяч пешек/объектов, бесконечных генераторов и глобального перехвата BaseGen. Масштабные крепости будут позже.
- Новые растровые ассеты сейчас не нужны: ссылки на существующие игровые графические пути/defs, без скачивания/перекопирования чужих модов. Реальные проверяемые пути; не придумывать имена текстур. Визуальные ограничения прототипа назвать явно.

### 3. Две связанные полноценные задачи
Первая — помощь на базе колонии с настоящим условием выполнения (например, запрос медикаментов/готовой еды с нативной передачей/приёмкой). Вторая открывается после первой и ведёт **вне базы**, например поиск пропавшей группы/полевого архива у заброшенного пункта связи. Вторая использует наш аванпост/специальный site и реальное достижимое условие: доставить/забрать конкретный предмет или вывести живого персонажа. Умеренный бой допустим в согласованном квесте, автоматические происшествия гостиницы не добавлять.
- Native QuestScriptDef/QuestNode/QuestPart API, реальные quest signals, состояния success/fail/expired, нормальная отмена, реальная доставка предметов/спасение. Нельзя выдавать победу/деньги просто по таймеру, симулировать доставку счётчиком или считать отсутствие ошибки выполненным квестом.
- Не нужны заранее заданные NPC из сериалов/оригинальных игр. Лорный твист о душе/синтах пока только намёк в архиве, никакой фиктивной механики иммунитета или демонов без реализации.
- Адекватные сроки и реальные награды/отношения, без бесконечной фермы серебра. Небольшая сохраняемая стадия цепочки (если требуется) с guard от дублей, корректной загрузкой и переносом между картами. Один принятый/завершённый этап не сбрасывается при перестройке ресепшена.
- Полный RU и EN для новых labels/descriptions/letters/квестов/сообщений, одинаковые плейсхолдеры, UI без внутренних имён методов. Не менять существующие переводы/экономику/потребности гостиницы.

## Техническая проверка и сдача
1. Candidate/Source/ только новые необходимые C# (минимум, без копирования всех существующих Source и без новых framework ради двух квестов), Candidate/Defs/ необходимые XML, Candidate/Languages/{Russian,English}/Keyed/ и при необходимости DefInjected. Конкретный список изменённых файлов в REPORT, DIFF.patch для существующих файлов, если без них нельзя; никаких молчаливых правок integration bootstrap.
2. build_candidate.ps1: snapshot Source + candidate overlay -> собственный Build/TurboMegaMod.dll; ссылки как Tools/build_assembly.ps1. Реально собрать. Для XML выполнить parse, поиск duplicate defName/key, сверку RU/EN/плейсхолдеров и всех новых cross-refs с настоящими Core/DLC/mod Defs, родителей Abstract/Name учитывать отдельно. Записать результаты в VALIDATION.json, неизвестные ссылки не считать существующими.
3. Candidate/Tests/InGameMinutemenHuntersProbe.cs и компиляция testDLL. Probe для будущего запуска Codex: проверить загрузку defs, создать допустимую фракцию/пешек, сгенерировать квесты через настоящие native nodes/TestRun, проверить реальное состояние цепочки и Scribe, подготовить site/map для осмотра и save/load. Функциональные ограничения честно разделить с ручной проверкой. Если полный вызов map generation из probe опасен, сделать проверяемый точный debug action и MANUAL-CHECKS вместо бесконечной автоматизации. Нельзя прямым присваиванием success/stage подменить испытание настоящих quest signals.
4. DESIGN.md (коротко: что игрок делает, лор, баланс, что действительно реализовано), FLOW.md (owning API/сигналы/сохранения/генерация), GUIDE.md на русском, MANUAL-CHECKS.md, REPORT.md с фактом компиляции и точными границами. Не заявлять native PASS или визуальный просмотр: игру запускает Codex.
5. Лучше законченные фракция+одна полноценная цепочка из2задач и рабочий небольшой site, чем десятки заглушек. При сложностях упростить оформление/необязательные расширения, но не скрывать отсутствие реального квестового цикла. Никаких fake fallbacks. Контент остаётся кандидатом до review Codex.
