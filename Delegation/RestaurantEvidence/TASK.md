# Gemini: история лицензий и проверяемые факты о ресторане

Пиши только в `Tools/Build/GeminiRestaurantEvidence/`. Предыдущие исходники доступны для чтения в `Tools/Build/GeminiRestaurantSurvey/`. Не меняй Git основного проекта, код, DLL, настройки, сохранения и результаты предыдущего задания. Не устанавливай пакеты, не запускай загруженные DLL, не связывайся с авторами. Можно клонировать публичные репозитории и получать их историю только внутри новой выходной папки.

Нужна механическая подборка доказательств для решения Codex. Юридических выводов, утверждений о совместимости и исправлений не делай.

1. Для `https://github.com/Zaljerem/Gastronomy` и `https://github.com/Zaljerem/CashRegister` выпиши полные лицензионные абзацы README, заголовки LICENSE, комментарии о правах в исходниках, ссылки на исходных авторов и upstream-репозитории. Каждая цитата должна иметь URL точного commit, путь и строки. Подтверди реальные SHA из предыдущего PINS.json.
2. В новых локальных клонах посмотри `git log --follow` для README и LICENSE: когда появились GPL-файл и CC BY-NC-ND-утверждение, кто и каким коммитом внёс их. Приведи конкретные diff и отметь любые явные разграничения кода/графики. Не выводи разрешение на перенос из одного наличия LICENSE. Если история недоступна, зафиксируй предел проверки.
3. В исходных проектах авторов (только ссылки, реально указанные в репозиториях) найди LICENSE/README на точном SHA. Публичное обновление лицензии, если есть, цитируй с датой и ссылкой. Не подменяй лицензии форка автоматически лицензией исходника.
4. Перепроверь спорные выводы своего прошлого отчёта: где именно старые `.stages.0.` действительно объявлены устаревшими, есть ли у соответствующей мысли `TKey`; если доказательства нет, замени утверждение на «требует проверки в игре». В Hospitality числовые индексы работали на нашей 1.7, поэтому одного индекса недостаточно.
5. Проследи ВСЕ обращения к `RegisterUtility` и жизненный цикл его кэша. Для каждой гипотезы об утечке или NRE перечисли необходимые условия и существующие очистки/проверки null. Статический словарь сам по себе не доказывает воспроизводимый сбой. Составь таблицу «подтверждено кодом / гипотеза / что проверить в игре». Не предлагай запрет гравикораблей как доказанное требование.

Выход: `LICENSE-EVIDENCE.md`, `HISTORY.json` (URL/SHA/путь/строки/изменение), `CLAIMS-REVIEW.md`, `REPORT.md`. Цитаты локальных файлов должны совпадать побайтно с указанным SHA. Итог нужен для быстрой независимой проверки, без длинного общего пересказа.
