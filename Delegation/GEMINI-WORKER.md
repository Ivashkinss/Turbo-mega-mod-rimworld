## Учёт исполнения

Очередь не изменяй. Разрешена запись в `Tools/Build/GeminiWorkerState/<id>.json` (явное исключение к ограничениям задания):

```json
{
  "id": "TaskId",
  "state": "running",
  "updatedUtc": "YYYY-MM-DDTHH:MM:SSZ",
  "report": "Tools/Build/<outputDir>/REPORT.md",
  "summary": "Коротко результат или ошибка"
}
```

`running`, `done`, `error`. `done` = выполнил задачу и проверки, это не «принято». Перед `done` проверь все `expectedOutputs`. При сбое `error` с конкретной причиной, бесконечно не повторять. После перезапуска сессии старый `running` не считать живым вторым процессом: при сомнении `error`, работу не дублировать.

Пользователю пиши коротко только при старте задачи, завершении или ошибке. Не выдумывай задания и не ставь задачи себе сам. Если видишь проблему вне задачи — опиши её в REPORT в разделе «Для Claude».
