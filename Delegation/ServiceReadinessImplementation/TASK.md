# ServiceReadinessImplementation — состояние служб на ресепшене

Сделай настоящий компилируемый кандидат следующего этапа. Пользователь хочет понятный единый ресепшен; прежде ему было непонятно, почему построены кровати, но никто не приходит. Нужна компактная справочная сводка фактической готовности, не очередная модель или аудит.

## Границы
- Читать неизменяемый Tools/Build/ServiceReadinessSnapshot/; проверь SNAPSHOT.json. Запись ТОЛЬКО Tools/Build/GeminiServiceReadinessImplementation/ и Tools/Build/GeminiWorkerState/ServiceReadinessImplementation.json.
- Не менять рабочие Source/Defs/Languages/Assemblies, Git, QUEUE, игру, настройки/сейвы; игру не запускать, сеть и GUI не нужны. Читать существующие compiler/reference DLL можно. Assembly-CSharp только через Cecil metadata, не исполнять.
- Кандидат Source + RU/EN Keyed, сборщик snapshot+overlay в отдельный Build/. Не трогать экономику, сохранения, расписание, ИИ, выдачу заданий, деньги и RNG. Не интегрировать чужие моды.

## Требования
1. На вкладке Общие в существующих Настройках служб комплекса одна кнопка Состояние служб. Никаких зданий, нижних вкладок, новых областей, автоматического исправления конфигурации.
2. Окно с прокруткой: Гостиница, Клиника, Ресторан, Продажи, Персонал. Только измеримые факты: например общая/служебная территория, фактические управляемые гостевые и медицинские кровати, занятые/доступные места (не обещать гарантированное заселение), выключенные службы, отсутствие раздаточного пункта или пустое меню, подходящие холодильники и физические порции, число активных хранилищ На продажу, включённая работа официанта/продавца/врача.
3. Сначала прочитай owning predicates: не выдавай физическое наличие за достижимость, эффективную готовность конкретному гостю или гарантированный инцидент. Нет надёжного общего Ready API — показывай конкретные факты/ограничения с корректным текстом. Число работников считать по существующим guard методам без вызова WorkGiver/генерации Job. Не менять роли, диеты и приоритеты ради чтения.
4. Для расписания только существующие разрешённые часы/дни/сроки, если есть доступное публичное состояние; не предсказывать дату прибытия и не подменять storyteller. Объясни, что готовые места не гарантируют немедленный визит. Не добавляй новые кнопки вызова посетителей.
5. Read-only сбор данных при открытии и отдельная кнопка Обновить, НЕ полный обход карты каждый GUI frame/tick и НЕ новый MapComponent/патч тика. Отложенная компоновка/scrollheight по содержимому, понятные русские формулировки без className/defName. Без вымышленных звёзд, процентов эффективности и FPS.
6. Null/потерянная карта/снесённый ресепшен/отсутствие DLL optional/DLC безопасны. Динамические Def/раса/фракции без фиксированного списка. GUI state/BeginScrollView восстанавливать try/finally. Длинные переводы не перекрывают показатели.
7. Candidate минимально затрагивает ComplexServicesDialog.cs и добавляет собственный ServiceReadiness.cs; существующие Ransom/Menu не переписывать. Все тексты в парных RU/EN Keyed с идентичными placeholders.
