# FactionRansomImplementation — самостоятельный кандидат следующего этапа

## Цель и объём
Пользователь просит крупную полезную задачу примерно на два часа самостоятельной разработки, пока у Codex обновляется лимит. Сделай рабочий, компилируемый кандидат выкупа раба колонии исходной фракцией, а не очередной обзор. Если закончишь раньше — сдавай готовое, не заполняй время лишними отчётами. Это СЛЕДУЮЩИЙ этап: текущие свободные трудовые договоры и панель персонажа Codex заканчивает сам. Обновление пользователя 17.11: саму механику ОБМАНА реализовать сразу; бунты, происшествия, нападения и карательные рейды отложены до сюжетной финалки. Никаких интимных механик.

## Изоляция — обязательна
- Единственный источник кода: неизменяемый снимок `Tools/Build/FactionRansomImplementationSnapshot/`. Он содержит Source, документацию, тест договора и описание сборки. Сначала проверь SHA256 по SNAPSHOT.json.
- Пиши ТОЛЬКО `Tools/Build/GeminiFactionRansomImplementation/` и свой обычный `Tools/Build/GeminiWorkerState/FactionRansomImplementation.json`. Ни Source/ рабочего проекта, ни XML/DLL/Git/QUEUE/игровые настройки/сейвы не менять. Не делать commit/push.
- НЕ запускать игру, браузер/GUI, установку инструментов, скачивание библиотек, системные настройки или другую фоновую работу. Имеющиеся compiler/refs/инструменты читать можно. Не ждать ответов Codex; разумные узкие решения записать в DECISIONS.md.
- Не перечитывай изменяющийся рабочий Source вместо снимка. Нет нужды копировать весь Components/ или игровые файлы. Ссылки на установленные зависимости — read-only.

## Согласованная механика
1. На ресепшене в существующем окне обычного самовыкупа можно предложить исходной фракции выкуп выбранного раба за установленную положительную сумму. Сохрани исходную фракцию ДО смены GuestStatus: slaveFactionInt очищается нативным переходом. Используй сохранённую ссылку, а не имя/жёсткий список фракций. В будущем будут модовые фракции.
2. Начальная вероятность согласия фракции 50%. Результат и сумма фиксируются при первом предложении и сохраняются; повторное нажатие/загрузка/изменение цены не дают повторной попытки. Не трогай глобальный RNG надолго; существующий WorkContracts.WillAccept — образец стабильного решения по pawn/world seed. Решение фракции имеет отдельный seed/состояние. Не реализовывай пока настройку шансов по отдельным фракциям.
3. Отказ фракции НЕ начисляет серебро и НЕ меняет статус пешки. После отказа доступен существующий обычный трудовой договор 90%/10%; не переписывай его архитектуру. Явно раздели отказ фракции и отказ работника.
4. Согласие даёт реальную разовую выплату колонии в виде физических стопок серебра около ресепшена. У фракций ванили нет общего доступного денежного счёта: это внешняя фракционная выплата, как страховые выплаты клиники, а НЕ изъятие монет из инвентаря гостя. Не выдумывай API казны фракции. Серебро создаётся один раз и хранится в сохраняемом ThingOwner-эскроу до размещения.
5. Доход комплекса увеличивается только на фактически размещённые новые монеты; частичный сброс, блокировка клетки, перезагрузка и повторный Process не дублируют выплату. Учёт выкупа отдельный от платы за комнату/медицину/продаж: НЕ пополняй бюджет уборки и не создавай заработок работника из платежа фракции. Сумма физического серебра = escrow + received; earned никогда не больше received.
6. Обычная честная ветка: после полной выплаты игрок может отпустить персонажа нативным маршрутом к исходной фракции. Не телепортировать, не удалять, не превращать автоматически в колониста. До ухода хранится явный статус «выкуп оплачен, ожидает освобождения». При закрытом выходе/падении/mental state/операциях действие безопасно откладывается. Освобождение повторно не вызывается; груз из рук не должен уничтожаться при ExitMap. Используй существующие проверяемые идеи WorkContracts.Complete, но не обнуляй заработок другого договора и не вызывай рабское SlaveRelease на уже свободной пешке. После полной выплаты добавь отдельное явное решение «Обмануть: удержать после выкупа». Оно переводит запись в сохраняемое состояние обмана, НЕ меняет уже полученное серебро и НЕ освобождает пешку. Сохрани факт обмана, тик решения, исходную фракцию и уплаченную сумму для будущего сюжета; не создавай рейд/бунт/насилие, не меняй goodwill скрыто. По повторному нажатию нет нового платежа/другой записи. Позднее честное освобождение остаётся доступным, но исторический факт обмана не стирается. В интерфейсе ясно предупреди, что это сознательное нарушение оплаченной договорённости, а сюжетные последствия будут подключены позднее. Не добавляй аналогичный обман работника по свободному трудовому договору: это другая ветка, сейчас задача только об уже оплаченном выкупе ФРАКЦИЕЙ.
7. Взаимоисключение: предложение фракции допустимо только для доступного раба колонии без уже принятого свободного трудового договора/постоянного присоединения/завершённого освобождения и без начавшейся другой выплаты. Нельзя оплатить одного персонажа двумя способами. Старые записи заработка и их квитанции не портить. Нулевую/исчезнувшую/игрокову исходную фракцию обрабатывать понятным отказом без мутаций. Враждебность сама по себе не требует жёсткого исключения фракции: переговоры могут быть с врагом, но не меняй отношения автоматически.
8. Не добавляй отдельные зоны, здания и нижние вкладки: управление только существующим ресепшеном. Сохранить packageId и существующие save keys. RU/EN новые строки параллельны, плейсхолдеры одинаковые, игроку ясно: шанс, одноразовость, сумма, отказ/оплата, ожидание ухода. Никаких обещаний готовых рейдов.

9. Чистое представление истории: различай «фракция отказала», «фракция оплатила, ждёт освобождения», «обман: удерживается после оплаты», «отпущен», включая вариант «отпущен после обмана». Старые флаги paid/released не должны противоречить новому этапу. Отказ фракции не является обманом.

## Формат кандидата
- `Candidate/Source/` — ТОЛЬКО новые или изменённые C# файлы с теми же относительными именами, полные тексты (не псевдокод). Предпочтителен отдельный FactionRansom.cs, минимальные изменения WorkBuyout/WorkContracts; текущие доходы и роли не переписывать.
- `Candidate/Languages/{Russian,English}/Keyed/FactionRansom.xml` — предлагаемые новые ключи.
- `Candidate/Tests/` — полезные тесты правил/переходов/сохранения, без зависания и без подмены проверки простым повторением реализации. Тест физического нативного выхода подготовить как исходник по аналогии со снимком, но НЕ запускать игру.
- `build_candidate.ps1` — воспроизводимая сборка ПО СНИМКУ с overlay Candidate/Source только в своей output папке. Read-only ссылки на Components и Tools/Build/RimRef-1.6.4871/ref/net472 как в снимке Tools/build_assembly.ps1. Результат только `Tools/Build/GeminiFactionRansomImplementation/Build/`. Нельзя перезаписывать основной Tools/Build/TurboMegaMod.dll или Assemblies. Никаких NuGet/install/network.
- `TEST-RESULTS.json` — точные реально запущенные проверки, команды, exit codes, выводы, границы. Не называть игровыми тестами сборку/математическую модель.
- `DECISIONS.md` <=50 строк: выбранные состояния/данные/точки integration и реальные открытые вопросы.
- `REPORT.md` <=80 строк: что реализовано, список изменённых файлов, схема состояний в простом тексте, как повторить сборку/проверки, что Codex должен проверить в игре перед переносом. Не создавай длинную общую документацию, отдельный генератор отчётов и десятки перепроверок схемы JSON.

## Обязательные приёмочные случаи
Покрой минимум эти 20 независимых случаев, без выдуманных PASS:
1) согласие 50%-ветки фиксируется; 2) отказ фиксируется; 3) save/load не перебрасывает ответ; 4) изменение цены после решения не меняет обязательство; 5) двойной клик не создаёт второй платёж; 6) пустая/игрокова исходная фракция не меняет состояние; 7) свободный контракт блокирует второй выкуп; 8) отказ фракции допускает старый трудовой договор; 9) заблокированный сброс сохраняет escrow; 10) частичный сброс с reload не теряет/не дублирует серебро; 11) счётчик дохода только по реально размещённым монетам; 12) разрушенный ресепшен не уничтожает escrow; 13) выход закрыт — оплаченная запись сохраняется без ложного released; 14) груз из рук сохраняется на карте перед уходом; 15) повторный release не платит/не освобождает дважды; 16) старое сохранение без новых полей загружается с безопасными значениями.
Дополнительно: 17) обман разрешён только после полной выплаты; 18) обман после reload не повторяет выплату и не очищает историю; 19) последующее освобождение оставляет исторический флаг обмана; 20) принятие решения не создаёт никаких рейдов, бунтов и скрытых смен отношений.
Нативно зависимые случаи можно оформить честными подготовленными сценариями, не выдавая их за исполненные. По возможности отдели чистые правила, которые действительно проверяются без игры.

## Самопроверка перед сдачей
Проверь diff кандидата относительно снимка, отсутствие чужих изменений и внешних записей. Успешная компиляция обязательна, если установленные compiler/refs доступны; если блокирует реальное API — покажи точную ошибку и оставь минимальный ремонтируемый код. Не маскируй ошибки заглушками, безусловными true, собственными копиями типов Verse, вымышленными сигнатурами. Работай содержательно до готовности результата, не заканчивай только анализом. После готовности обнови worker state на done с фактическими результатами; QUEUE не трогать.
