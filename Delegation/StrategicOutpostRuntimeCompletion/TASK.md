## Конкретные оставшиеся дефекты CoreMapMerge (проверить, если MapIntegrity уже исправил — сохранить)

1. `DoDailyProduction()` остаётся публичным и обходит общий дедлайн/Physical guard. `Tick`/`TriggerDailyProductionNow` его проверяют, но этот публичный вход — нет. Один guarded cycle для всех входов, raw производитель private. В ветке не-фабрики создаётся одна вещь `stackCount=wholeUnits`, что превышает stackLimit; результат TryAdd может теряться. Использовать уже существующий `ProductDef.ProduceInto` либо корректно создавать/хранить стопки с подтверждением, не создавать непринадлежащие бесхозные Thing. Зачёт дроби/рабочего дня не должен давать повторно выпуск при отказе/повторном вызове.
2. `RecallPersonnelToAutonomous`: сейчас делается `Workers.TryAdd(p,false)` для всё ещё Spawned пешки, без DeSpawn и без проверки bool; потом IDs очищаются и режим считается автономным. В native ThingOwner<T>.TryAdd нет автоматического DeSpawn! Требуется реальный переход Map→owner с сохранением личности/инвентаря/WorldPawns регистрации, проверка каждой операции и откат/отказ без двойного владения. Не перечислять изменяемый `AllPawnsSpawned` прямо во время DeSpawn (копия). Для размещения на карте сначала подтвердить все допустимые spawn cells и способность разместить, не отнимать holder до невалидной клетки. Учитывать carry/job cleanup. Ментальные срывы/бой/недоступный живой участник не должны позволять спрятать его или телепортировать из чужого каравана. Посторонние приезжие остаются отдельно от штатного состава.
3. `AddPawnFromCaravan` пока проверяет лишь Dead/Faction и Workers.Count: не проверяет подходящего свободного колониста/режим Physical/общую занятую вместимость; можно держать дополнительные скрытые Workers при уже развёрнутом составе. Условия проверять в actual methods. Два основателя+вьючные животные должны по-прежнему работать. `TryUpgrade(localCaravan)` проверяет деньги любого переданного каравана, без co-location/принадлежности; чужой/удалённый караван нельзя использовать как кассу. Сохрани transactional upgrade planner MapIntegrity.
4. `AbandonAndEvacuate` удаляет вещи из owner и вызывает GiveThing без подтверждения/весового контроля. Если Workers пусты, но cargo не пуст и каравана нет, всё равно удаляет объект мира. Нужно переносить через безопасный mass-aware Withdraw/owner transfer и проверять фактическое принятие; недоперенесённое остаётся на аванпосте, объект не удаляется. Карта/развёрнутые пешки/строения: проверить реальный native жизненный цикл MapParent при снятии, не осиротить карту или потерять людей/животных. При неподдержанном безопасном сворачивании явный отказ предпочтительнее фиктивного успеха. Нельзя молча удалить склад/пешек. Локализовать новые причины/имеющиеся hardcoded английские отказы режимов.
5. `DoDailyShipment` передаёт вещи из owner в DropThingsNear, затем слепо Remove всех исходных ссылок. Сверить реальное IL принятия в капсулу/карты: оставшиеся непринятыми вещи нельзя удалять. Точная колония-получатель должна сохраняться; отсутствие/блокировка не теряет товар, не создаёт повторную отправку после reload. Держать изменения ограниченными этому адаптеру, не переписывать общие службы комплекса.
6. Проверка производства должна учитывать выбранную специализацию, реальный Research/Recipe/WorkType, реальные количества ингредиентов и legal skills<=20. Никаких минимальных навыков, отсутствующий/отключённый труд даёт0. Переходы режимов и новые назначения не приносят задним числом день физического труда. Не терять Core текстильные исследования/рецепты и четыре типа аванпостов.

## Заменить фиктивные тесты реальной приёмочной пробой

Текущий merge `Tests/InGameStrategicOutpostsProbe.cs` объявляет PASS, например, за проверку selectedProductDefNames.Count==2 («разделение труда»), наличие RecipeDef («списание ингредиентов»), кладёт chemfuel в owner («evacuation verified»), создаёт просто `new StrategicOutpost` без настоящего основания/мира. Это НЕ доказательства требуемого поведения; не оставлять такие заявления как native checks.

Нужен нормальный launchable MapComponent/StaticOnStartup с флагами `-tmm-outpost-probe` и `-tmm-outpost-reload`, настоящим GameDataSaveLoader.SaveGame("TMM-StrategicOutpost") и отдельной веткой LoadGame. Проба только своей копии мира: реальные взрослые колонисты/караван/основание через production method, ровно2основателя+животное+реальные вещи, те же ThingIDs. Количество/навыки легальные. Фикстурные начальные реальные монеты/ингредиенты можно явно создать в holder для проверки расхода (с ограничением stackLimit); это test setup, не доход игрового мода.

В ходе естественных тиков проверить одни сутки производства (Superfast допустим; глобальное время не присваивать, production deadline не отматывать для выдачи бесплатного дня). В тот же день повторный публичный вызов не создаёт товар. Для чистой арифметики можно отдельные model assertions, но отделять их от настоящего производства. Настоящий депозит/стоимость upgrade/сырьё/реальные результаты рецепта/выбор двух продуктов и нулевой навык; генерация карты и безопасный L2/L10 upgrade с настоящими bed/CanReach/planner checks из MapIntegrity; свободно построенный объект/повреждение сохраняется при повторном визите; actual Deploy/Recall сохраняет pawn ownership и не даёт двойной труд; отмена эвакуации с перегрузом сохраняет оставшийся груз; реальные Save/Load сохраняют IDs/держателей/остатки/дедлайн. Можно несколько последовательных стадий одной пробы, не огромная регрессия всех служб. В тесте не заменять production методы mock-реализацией и не сериализовать вручную клонами.
