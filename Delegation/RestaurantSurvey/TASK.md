# Gemini: механическая инвентаризация будущего ресторана

Цель — собрать проверяемые исходные данные для следующего этапа. Не интегрировать моды и не запускать загруженный код.

Единственная разрешённая папка записи: `Tools/Build/GeminiRestaurantSurvey/`. Не менять корневой Git, Source, Components, Defs, Languages, Assemblies, настройки или сохранения игры. Не устанавливать программы/пакеты, не входить в аккаунты и не запрашивать секреты. Допустим `git clone --depth 1` публичных репозиториев внутрь выходной папки; не выполнять git-команды в корне нашего проекта. Если публичная загрузка не получается — описать ошибку, не менять GitHub-авторизацию или системные настройки.

Официальные исходники:
- `https://github.com/Zaljerem/Gastronomy`
- `https://github.com/Zaljerem/CashRegister`

Для каждого сними точный commit SHA и ветку. Прочитай About/About.xml, LoadFolders.xml, LICENSE*, README*, csproj и состав ветки 1.7. Скопируй тексты лицензий/README в отчётную папку без правок. Не делай юридических выводов: если README и LICENSE расходятся — приведи точные формулировки и пути, разрешение на перенос проверит Codex.

Выход:
1. `PINS.json`: URL, SHA, ветка, packageId, заявленные версии игры, обязательные зависимости из About, TargetFramework из csproj, реальные DLL/AssemblyRef для 1.7 (если можно безопасно прочитать метаданные без запуска DLL).
2. `FILES.json`: отсортированный список ресурсов выбранных папок загрузки 1.7 и общих папок — путь, размер, SHA256. Указать все условные ветки и не смешивать их с обязательными.
3. `LOCALIZATION.json`: число реальных Keyed/DefInjected записей EN/RU, отсутствующие/устаревшие ключи, несовпадения числовых параметров. XML-комментарии не считать записями; старый `<rep><path>...` формат обрабатывать отдельно. Русские gender/numCase-селекторы не считать потерей параметров сами по себе. Перевод пока не переписывать.
4. `REPORT.md`: зависимости ресторана, известные ограничения (особенно Odyssey/гравикорабли), точные ссылки/файлы/строки. Найти в C# проверки packageId/названия Hospitality и CashRegister, важные для нашего объединённого пакета. Никаких предположений о фактической совместимости: это только статическая инвентаризация.

Состояние нашего проекта для контекста: Hospitality уже загружается внутри Turbo mega mod, packageId всей сборки остаётся `colonyproject.integrated`; используется встроенная Harmony и один общий 0MultiplayerAPI из AdaptiveStorage. Наша гостиница получает собственную посуточную оплату, исходные имена классов Hospitality сохраняются. Другие моды ещё могут не распознавать её по старому packageId — такие проверки нужно перечислить, самостоятельно не исправлять.

В конце сообщи пути к отчётам. Codex независимо проверит результаты перед переносом.
