# Gemini: точки выплаты и обычный самовыкуп — проверочные данные

Читать только `Tools/Build/ServiceIncomeSnapshot/` и SNAPSHOT.json. Запись строго в `Tools/Build/GeminiServiceIncomeAttribution/`. Не менять Source/Defs/Languages/Assemblies/Git, игру, настройки/сохранения и прежние отчёты. Без сети, установки пакетов и запуска игры/DLL.

ВАЖНО: снимок Company.cs содержит СТАРУЮ схему личного кошелька. Пользователь её отменил: Codex сейчас меняет реализацию. Новая схема относится только к ОБЫЧНОМУ общению без постели/интимных действий и другим обычным гостиничным работам. Гость платит колонии. Если сотрудник участвует в обычном договоре самовыкупа, услуги без расходников дают100% фактически принятой суммы в прогресс договора, с расходниками50%. Не создавать заработок без фактической услуги/оплаты. Отказ от необязательной беседы не штрафуется. Один платёж нельзя целиком начислить нескольким людям. Новые квесты, фракционный выкуп, освобождение/рейды ещё не готовы — не объявлять их реализованными.

1. `PAYMENT-POINTS.json`: точные методы/пути/участники/порядок мутаций в снимке для CompanyService.Finish/Process, RestaurantService.Deliver, ClinicBilling.Discharge/ClinicAccounts.PlaceReceipts и Billing_Tend_Patch. Для каждого указать, известен ли конкретный исполнитель, доступен ли физически размещённый размер выплаты, есть ли уникальный id операции и какая часть сохраняется. Не предлагать правки кода.
2. `CASES.csv`:24 арифметических/состояниевых примера. Колонки id, service, received_silver, consumables, contract_active, target, credited_before, carry_before, expected_credit, expected_carry, expected_remaining, duplicate, expected_colony_income. Обычное общение100%; питание50%. Для дробной половины допускаем накопление остатка:1серебро за блюдо дважды даёт суммарно1взноса. Не превышать остаток договора, но вся реально полученная выручка остаётся доходом колонии. При отмене/возврате/неуспешном размещении0. Повторная обработка того же id не даёт повторного дохода/взноса. Без договора прогресс0, доход колонии сохраняется. Для клиники с несколькими врачами не придумывать распределение — отдельная неопределённость.
3. `REPORT.md`: до10фактов/неопределённостей с путями. Проверить CSV и арифметику своим скриптом внутри выходной папки. Чётко отделить предложенную модель контрольных данных от текущего поведения старого снимка. Это подготовка проверки Codex, не выполненные игровые тесты.
