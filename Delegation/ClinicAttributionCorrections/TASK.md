Codex нашёл конкретные ошибки:

- ВСЕ реально поступившие монеты остаются колонии. Зачёт самовыкупа — счётчик, а не денежная выплата сотруднику. В case01 paid50 означает colony_retained_coins50, не0; во всех новых событиях колонка равна фактически учтённой выручке.
- validate.py не проверяет buyout_credits_detail, half_remainders_detail, colony_retained_coins, final_bill_amount. Контрольная копия с DocA:999999, colony=-1 и bill=-999 всё равно даёт PASS (REVIEW.json). Требуется реальная независимая проверка каждого ожидаемого числа.
- duplicate с заранее занулённым входом paid_coins не проверяет дедупликацию. Нужны входные ID квитанции и ненулевая повторная сумма: повтор ID даёт0 нового зачёта/учёта дохода.
- Case17 не содержит входного остатка цели, case18 — входного halfRemainder. Нельзя вычислить их ожидания из данных строки; добавить явные входы.
- Клиника создаёт фракционное вознаграждение. Бедность пациента не делает выплату нулевой; убрать ложный penniless-case и фразу о нехватке личного серебра.
- Факт «Notify_IterationCompleted никогда не вызывается при провале» не доказан переданными исходниками. Указать границу знания, не утверждать поведение движка. Нулевая выплата при провале определяется фактическим Hospital.SurgeryFailed (обнуление Bill), а не догадкой о вызовах.
- Формула итогового счёта учитывает ограничение AddToBill ДО множителя и ограничение Discharge ПОСЛЕ него: для положительных последовательных вкладов `floor(min(4000, min(4000, sum(claims))*multiplier))`. Пример5000, множитель0.5 =>2000, а не2500.
- Перевязка без лекарства в исходнике стоит0. Платный чистый труд в примерах обозначать как существующую временную часть операции, не придумывать цену перевязки50.
