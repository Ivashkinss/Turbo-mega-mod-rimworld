# FactionContentRegistry — перенести новый фракционный концепт в каталог данных

Пользователь добавил два документа и просит включить их в общий план. Root уже обновил Documentation/FACTIONS-CONTENT-PLAN.md. Это механическая подготовка будущего контента, а не разработка пятнадцати фракций сразу. StrategicOutpostsFoundation и MinutemenHuntersPrototype сданы; их код не менять. Приоритет root остаётся у проверки стратегического ядра.

## Изоляция и источники

Вход только Tools/Build/FactionContentRegistrySnapshot/; проверить SNAPSHOT.json. Полные авторские материалы в DesignSources/ — источник имён/снаряжения, FACTIONS-CONTENT-PLAN.md — актуальные решения, STRATEGIC-SETTLEMENTS-DESIGN.md — связь с миром. Запись только Tools/Build/GeminiFactionContentRegistry/ и Tools/Build/GeminiWorkerState/FactionContentRegistry.json. Root Source/Defs/Languages/Assemblies/Documentation/QUEUE/Git не менять; другие кандидатные каталоги не менять. Не запускать игру, сеть, DLL или сторонние setup. Никаких новых ассетов, загрузок или канонических «исправлений» по памяти. Worker state running → done с report path.

## Подготовить

1. **FACTIONS.json**: ровно 15 стабильных смысловых ID (это ID каталога, не будто существующие defName), русское название, роль, отношение из текста либо null если не задано, стиль базы, снаряжение, технологии и одна легендарная награда с желаемыми эффектами. Vanilla raiders отдельной записью retainedVanilla, не шестнадцатая новая фракция. Vault-Tec и Британские Просвещённые отдельны. Каждая строка содержит source file/line и статус planned. Числа/эффекты из концепта отличать от утверждённых правил игры и предложений Codex. Не объявлять предметы/способности/биологию реализованными. Новые имена/дополнительные фракции не выдумывать.
2. **CHARACTERS.json**: все именные персонажи второй входной записи по каждому направлению. Разделить парные строки (Мег и Руби; Захария и Наоми; Руфус и Эллен; Дейзи и Гоб и т.д.) на отдельных персонажей. Сохранить исходное написание/алиасы и особенности внешности/роли; не терять человека ради цифры «5–8». Отметить кандидатов в лидеры только когда роль явно задана; иначе null и причина. Ник Валентайн — одна личность с возможными связями, не два разных героя. Эдем — ИИ-терминал, не подтверждённый humanlike Pawn; ПАМ, Лебедь, сверхъестественные существа требуют своего представления. Не заполнять отсутствующие BodyTypeDef/HeadTypeDef/PawnKindDef выдуманными существующими ссылками. Имена из смешанной хронологии — proposed crossover, не проверенный канон.
3. **COVERAGE.md**: короткая матрица, где отражены все разделы первого входа (фракции/оружие/15 наград/базовые и фракционные исследования/аксессуары и операции/мебель) и второго (4 ранга/внешность/персонажи). Что не вошло в JSON — точный указатель на сохраняющий пункт плана, без пропуска «неудобных» идей. Отдельно сохранить ограничения: ранг не уровень базы, 10 уровней и cap level+1, уникальные герои/награды, Anomaly conditional, почва 200/222 без второго стака, балансируемые абсолютные эффекты, происшествия/рейды отложены.
4. **validate.py**: автономная структурная проверка JSON, 15 уникальных faction IDs/15 наград, уникальные character IDs и корректные связи, ссылки на существующие входные файлы/строки, отсутствие implemented/live-pass утверждений. Source refs должны вести на действительно относящийся к записи фрагмент. Сравнить извлечённый список имён с исходником, вручную выписать правила разбиения сложных строк в REPORT. Скрипт не пишет вне своего выхода, не загружает Assembly-CSharp. Не выдавать проверку структуры за доказательство баланса или точности канона.
5. **REPORT.md**: что создано, число карточек/персонажей, точные результаты реального валидатора и краткий список неоднозначностей для root. Не заявлять готовность gameplay, генерации NPC/карт, совместимость 1.7, игровое тестирование или согласие пользователя с новыми балансными предложениями.

Предпочтителен компактный полезный каталог для последующего кода, без сотен страниц эссе, нового «движка» тестов и повторного обзора библиотек. Root самостоятельно примет и использует данные при разработке первой фракции; production сейчас не меняется.
