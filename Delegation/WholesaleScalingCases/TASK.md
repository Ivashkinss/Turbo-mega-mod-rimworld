Правила:
1. В сумму V включать только фактически продаваемые вещи в помеченном player-owned хранилище внутри действующего комплекса. Вещь должна быть tradeable и иметь положительную конечную unitMarketValue. Частный склад без доступного работника доставки не считать доступным для покупки. Один thingID учитывать один раз, даже если одну запись перечислили несколько ячеек. Дубликаты в сценариях должны быть идентичными, не изобретать правило разрешения противоречивых данных.
2. Свободное количество `max(0, count-clamp(reserved,0,count))`; V=sum(freeCount*unitMarketValue). Число стэков само по себе не влияет:100стали в1или100стэках при одинаковой цене дают одинаковый V.
3. При V<=0 оптовый визит не назначается, delayTicks=null, budget=0. Иначе `delayDays=max(0.75, 4/sqrt(1+V/2500))`; `delayTicks=ceil(delayDays*60000)`; `budget=min(30000,max(1000,ceil(V*0.5)))`. С ростомV бюджет не уменьшается, интервал не растёт. Максимум2 одновременно находящиеся на карте оптовые группы; при2новую не спавнить.
4. Перед реальным спавном пересчитать текущий ассортимент. Если комплекс выключен/нет подходящей нейтральной или дружественной фракции/нетV, спавн отменяется. Старое snapshotValue не является разрешением приехать за уже проданным товаром. Новая группа действительно должна получить budget серебра в будущей реализации; сама таблица ничего не генерирует.
