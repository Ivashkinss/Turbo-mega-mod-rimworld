1. `MPI-REFS.json`: все TypeRef/MemberRef на `0MultiplayerAPI` из Hospital.dll 1.6 и 1.7 — полные типы, методы, параметры, возвращаемые типы/поля. Для каждого указать, есть ли соответствующее определение в нашем поставщике. Сверять сигнатуры/арность generic, а не только имена. Сохранить версии/размеры/SHA256 всех трёх DLL. Отдельно указать непроверенные generic/inherited случаи, не объявлять их совместимыми по догадке. Привести, когда вызывается каждый API по исходнику (без утверждений о реальной работе Multiplayer).
2. `METHODS.json`: точные имена типов/методов/сигнатуры/видимость и пути/строки в Source плюс соответствие в бинарнике 1.7 для: списка доступных медицинских кроватей, IsOpen/CanSpawnPatient, регистрации уже существующей пешки как пациента (если такой API есть), приёма через инцидент, получения PatientData, выписки/отказа, расчёта счёта и создания серебра, сохранения статуса оплаты. Если API нет — так и написать, не проектировать его.
3. `FLOW.md`: короткая карта вызовов от завершения лечения до выдачи серебра. Где флаги меняются относительно создания/размещения монет? Какие именно события могут повторно вызвать расчёт? Что уже предотвращает повторную оплату? Какие места только гипотетически опасны? Никаких исправлений исходников.
4. `REPORT.md`: факты/ограничения и список предложенных точек интеграции с точными исходными ссылками, без игровых или юридических заключений.

Контекст: в гостиничном комплексе будет отдельная разрешённая область клиники. Нужно ограничить именно больничный пул кроватей, сохранив обычные медицинские кровати колонии. Режимы сотрудников «только колония / только комплекс / оба места» реализует Codex; патчить их самостоятельно не нужно. Счёт гостя ресторана оплачивается из его кошелька; Hospital может выдавать вознаграждение иначе — это необходимо описать точно, не подменяя механику.
