# StrategicOutpostMaps — посещаемые базы аванпостов и развитие 1–10

Выполнять ПОСЛЕ StrategicOutpostsCorrections. Пользователь оставил нас работать до завершения аванпостов/расселения/видимых групп. Root делает региональное размещение и карты NPC; отдельный Codex-агент — реальные мировые караваны. Ты продолжаешь собственное ядро: настоящие сохраняемые карты наших аванпостов, растущие при улучшении. Не дублируй NPC clustering/world movement и не начинай фракционный сюжет.

## Вход и изоляция

Вход: уже завершённый Tools/Build/GeminiStrategicOutpostsCorrections/Candidate и его build/REPORT, immutable Tools/Build/StrategicOutpostMapsSnapshot (2rootSource/описание и native map API), прежний StrategicCorrectionsSnapshot для общей основы. Не меняй сданные output/корневые Source/Defs/Languages/Assemblies/Tools/Tests/QUEUE/Git/игру/сейвы. Пиши только Tools/Build/GeminiStrategicOutpostMaps/ и Tools/Build/GeminiWorkerState/StrategicOutpostMaps.json. Читай native DLL через Cecil, не исполняй её. Игру запускает root. Все утверждения о runtime PASS до запуска root запрещены.

## Цель игрока

Отправленный караван может **посетить свой аванпост**, увидеть и использовать реальную базу, людей, кровати и мастерские. Основание2колонистами, cap L+1, оплаченные серебром улучшения1–10 растят базу, оснащение и защиту. Карта не генерируется заново при повторном визите/загрузке/улучшении. При отсутствии визита сохраняется суточное автономное производство и отправка товаров.

## Реализация

1. Native MapGeneratorDef/GenStep и native caravan entry на свой MapParent. Продуманный небольшой базовый лагерьL1, далее доступные проходы/жилые/складские/рабочие модули, оборудование по специализации и технологии. НаL10 минимум11настоящих пригодных кроватей; наL1 минимум2. Двери, крыши/опоры, свет/электропитание, стол/сиденья, пешечные пути, защита с ростом уровня. Не запечатывать жителей и не заменять объекты декоративными метками. Используй подтверждённые Core defs/graphics, без новых скачанных ассетов. Не создавай бесплатных изделий/серебра в запасах.
2. Предпочтительна простая модульная планировка: новые комнаты/секции добавляются при апгрейде. Уже посещённую базу, постройки/вещи игрока, повреждения, имена и Pawn не стирай. Если нет безопасного места для обязательной новой секции — либо корректный вариант другой свободной позиции, либо отказ ДО списания серебра. Выполнение одного апгрейда не дублируется после reload. Не вводи дополнительные скрытые материальные счета поверх согласованной серебряной цены. Прототипные цены500×1.6 всё ещё балансируемые defaults.
3. **Одна работа одного человека:** при физическом управлении те же настоящие сотрудники выходят из pawnOwner на карту и выполняют обычные работы, абстрактный труд за это время отключён. Есть понятная команда вернуть аванпост в автономный режим; подтвердить перемещение настоящих Pawn обратно в owner с экипировкой/инвентарём, прекращением текущих jobs и сохранением всего имущества карты. При угрозе/бою нельзя прятать людей в owner для неуязвимости. Не переносить автоматически колонистов из приезжего каравана в постоянный штат.
4. Допустимо сохранять карту загруженной, пока управленческий режим autonomous хранит назначенных работников в owner (без Spawned двойников). Это уточнение прежнего blanket HasMap pause: решающий критерий — те же работники действительно НЕ трудятся физически. Явный сохраняемый режим/ростер, reconcile load/entry/exit, отсутствие catch-up за физические сутки. Такой вариант честно описать как ограничение TPS: не обещать выгрузку/hibernate map, если её нет. Не пытаться ради выгрузки deep-сериализовать весь native Map внутри другого owner.
5. Настоящие сырьё/груз, ручной перенос/отправка/посещение не дублируют предметы. Определи простой понятный пункт снабжения/склад: либо существующий owner-склад и команды выдачи/приёма, либо свои выделенные реальные клетки/здание с holder; не считать все вещи карты автоматически сырьём для абстрактной фабрики. Автономная суточная поставка продолжает работать после повторного визита и возврата к автономности. Отсутствующий получатель/блок доставки сохраняет груз.
6. Native save/load карты и worldObject сохраняет владение/состояние, собственные поля default/migration. Для ранее world-only созданного форпоста первая карта создаётся один раз с текущим уровнем; оставшиеся реальные вещи/пешки корректно передаются. Не телепортировать караван посетителя в соседнюю чужую базу. Чужие/старые NPC карты и гостиница не меняются.
7. RU/EN короткие понятные команды/подсказки, состав/режим/уровень/стоимость/посещение/автономность, реальные иконки. Не четыре новых нижних вкладки. Завершённый UI без видимых raw enum/defName и английских заглушек.

## Проверка и сдача

Полный новый overlay Candidate/{Source,Defs,Languages,Tests}, включающий необходимые правки к StrategicOutpostsCorrections. Файлы, не изменившиеся от исправленного кандидата, можно копировать в overlay для однозначной сборки, root сверит. build_candidate.ps1 строит snapshot общего source + исправленное ядро + этот overlay без дубликатов, compile probe отдельно. Поддерживай root Source/RegionalSettlements.cs/SettlementMaps.cs как read-only snapshot; не переписывай их.

Одна содержательная launchable native проба MapComponent/flag/report/save+reload: настоящий caravan→основание→первая native карта→те же люди/вещи, минимальные кровати и путь двери; улучшение и дополнительная комната без стирания вручную поставленного объекта; реальный save/load; возврат в автономный режим без дубликата людей/суточной продукции; повторный визит сохраняет карту. Нормальные навыки<=20, no fake success. Допустим контролируемый дедлайн дня и отдельный тест производственной функции с ясной границей. Учитывать runtime/errors/refs будет root.

Сдать build_candidate.ps1, DIFF.patch, DESIGN.md (реальный цикл/ограничения), GUIDE.md, MANUAL-CHECKS.md, REPORT.md, VALIDATION.json. Честно назвать неподдержанные позиции фабрики/температуру/питание/выгрузку карты, не выдавать весь стратегический мир за готовый. При непредвиденной сложности упрощай декор, сохраняя реальную карту, идентичность/владение и одноразовость улучшений.
