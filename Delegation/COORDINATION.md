## Роли

| Агент | Где работает | Роль |
|---|---|---|
| **Gemini** (Antigravity) | локально, с терминалом, лимит практически без ограничений | **Основной исполнитель всего объёма.** Реализует кандидатов, сам их проверяет (самоаудит по чек-листу ниже), вливает принятые кандидаты в корень (задачи `integrate`), собирает DLL, гоняет игровые тесты и reload, разбирает логи, пишет и обновляет документацию, CONTINUE/HANDOFF по поручению, локализацию и ассеты. Делает локальные коммиты в задачах `accept`, которые Claude назначил ему. Опрашивает очередь каждые 5 минут. |
| **Claude** (root) | Claude Code (desktop), локально, с терминалом | **Только решения и короткие тексты.** Ведёт очередь, пишет короткие TASK.md, проверяет выборочно: читает REPORT/VALIDATION/Result.json и самые рискованные куски diff, а не файлы целиком. Решает, что принято. Корень правит сам только для мелочей (несколько строк), когда TASK для этого дороже самой правки. Терминал использует экономно: сам игровые тесты не гоняет, а ставит задачу `run` для Gemini. Исключение — пользователь прямо попросил или Gemini недоступен. |
| **Codex** | локально, с терминалом, дорогой лимит | **Редко, точечно.** Независимая приёмка перед коммитом только для опасных зон (жизненный цикл пешек/WorldPawns, сохранения/Scribe, Harmony-патчи, платежи и поставки аванпостов) и арбитраж, если Claude и Gemini расходятся. Опрашивает очередь раз в 30 минут; если задачи нет, сразу останавливается. Разовая задача Codex должна укладываться в один короткий сеанс. |

Claude не опрашивает очередь сам. Он видит результаты, когда пользователь пишет ему в чат («проверь очередь»). Поэтому каждый исполнитель обязан оставлять результат в файлах так, чтобы его можно было понять без переписки и без чтения всего кода.

## Очередь

Единственный реестр задач — `Delegation/QUEUE.json`. Редактирует его **только Claude**. Поля задачи:

- `id`, `taskFile` (внутри `Delegation/`), `outputDir` (внутри `Tools/Build/`), `expectedOutputs`
- `assignee`: `gemini` | `codex`. Нет поля — считать `gemini` (старые записи).
- `state`: `pending` → исполнитель берёт; `assigned` (выдано вручную), `reviewed`/`accepted`/`rejected` — решения Claude.
- `kind`:
  - `implement` — кандидат в outputDir, корень не меняется;
  - `integrate` — перенести уже одобренный Claude кандидат в корень; разрешены только файлы, перечисленные в TASK.md;
  - `run` — сборка, игровые тесты и логи по готовой команде;
  - `accept` — финальная проверка и локальный git commit.
- `afterTask` (необязательно): брать задачу только после `done` указанной задачи. Так Claude может выдать сразу цепочку `implement → integrate → run`, не дожидаясь чата между шагами.

Исполнитель берёт только задачи со своим `assignee` и только `pending`. Одновременно одна задача на агента. Чтобы Gemini не простаивал, Claude по возможности держит в очереди 2–3 задачи вперёд.

## Подтверждения (ACK)

- Gemini: `Tools/Build/GeminiWorkerState/<id>.json`
- Codex: `Tools/Build/CodexWorkerState/<id>.json`

Формат: `{"id","state":"running|done|error","updatedUtc","report","summary"}`. `done` = задача и её проверки выполнены, это ещё не «принято».

## Отчёт, экономный для проверяющего

`REPORT.md` в outputDir — не длиннее примерно 60 строк:

1. Итог одной строкой: PASS / FAIL / частично.
2. Изменённые файлы с числом строк diff.
3. Точные команды, exit code, путь профиля `TestRuns/...`, ключевые поля `Result.json`/`*Probe.json`: passed, checks, runtimeErrors, unresolvedReferences, gpuLost, SHA256 DLL.
4. **«Куда смотреть Claude»** — 3–7 мест `файл:строка`, где решение рискованное или неочевидное. Claude читает в первую очередь их.
5. Что НЕ проверено.
6. Самоаудит Gemini (см. ниже), пункт за пунктом: да/нет.

Без пересказа проекта и без общих слов «всё надёжно».

### Самоаудит Gemini перед `done`

- Нет check-ов, которые засчитывают PASS за существование Def/типа или за компиляцию.
- Нет запасного «статического» пути, который ставит PASS, если карта/игра не дошли до нужного состояния.
- Сравнение с живым корнем: корень после снимка не менялся, либо изменения перечислены. Не потеряны прошлые исправления, названные в TASK/HANDOFF (например, `GenStuff.DefaultStuffFor` fallback, lifecycle, shipment).
- Не тронуты файлы вне разрешённых.
- Для `run`: `Assemblies/TurboMegaMod.TestProbe.dll` отсутствует, игра закрыта, пользовательские сейвы и настройки не менялись.

## Кто что пишет

- Корневые `Source/ Tests/ Defs/ Languages/ Patches/ Textures/ About/ Documentation/*.md` — Gemini в задачах `integrate`/`run`/`accept` (только перечисленные в TASK.md файлы), Claude — мелкие правки.
- `Assemblies/TurboMegaMod.dll` — только через `Tools/build_assembly.ps1`.
- `TestRuns/` — изолированные профили тестов.
- `Documentation/*-FullSet.json`, `*-Reload.json` и прочие итоговые отчёты тестов — пишут сами тестовые скрипты.
- `CLAUDE-HANDOFF.md`, верх `CONTINUE.md`: Gemini пишет черновик в задаче, Claude правит итог.
- Git: коммит только в задаче `accept` или по прямой просьбе пользователя. Не коммитить `TestRuns/`, логи, сейвы, `Tools/Build/`.
- Push (решение пользователя 18.11.2026): после каждого крупного обновления Claude сам отправляет `main` на GitHub, не спрашивая. Крупное обновление — этап или функция, принятые по настоящему прогону в игре, или существенное изменение правил и архитектуры. Мелкие правки документов и очереди уходят вместе со следующим крупным. Gemini и Codex не пушат, если их TASK.md этого не разрешает. Без force push; перед отправкой проверить, что ветка не отстаёт от origin.

## Жёсткие правила проекта (наследуются)

1. Все изменения только внутри папки мода. Не трогать оригинальные моды, игровые файлы, настройки и пользовательские сейвы. packageId `colonyproject.integrated` не менять.
2. Игровые тесты: только если RimWorld не запущен (скрипты это проверяют; если пользователь играет — `error` «игра запущена», без ожидания и без убийства его процесса). Закрывать только свой процесс. После теста `Assemblies/TurboMegaMod.TestProbe.dll` должен отсутствовать.
3. Принятие — только по настоящему прогону в игре: `Result.json`/`*Probe.json`, `runtimeErrors=0`, без `VK_ERROR_DEVICE_LOST`, без нерешённых ссылок. «Компиляция успешна» и слова отчёта — не доказательство. Проверка, которая засчитывает PASS за сам факт существования Def, — фиктивная.
4. Не копировать frozen-снимки `Tools/Build/*Snapshot/RootSource` поверх живого `Source/`.
5. Не трогать без отдельной задачи: `StrategicOutpost.cs`, `StrategicOutpostPawnLifecycle.cs`, holders, платежи/поставки/режимы аванпостов, world traffic.
6. Игровой `Assembly-CSharp` не исполнять в хост-процессе — только Cecil/компилятор. Cecil вызывать только из файла скрипта в `Tools/` (например, `Tools/cecil_check.ps1` с параметрами) и никогда не вызывать через `powershell -Command` с `[Reflection.Assembly]::LoadFrom` в строке. 19.11 Windows Defender принял такую строку за троян Commando.B!ml и остановил процесс. Исключения в антивирусе не добавлять: это настройки пользователя.
7. Если корень (`Source/` и т. п.) изменился после снимка, на котором делалась задача, — сообщить об этом в REPORT, не «чинить» корень самостоятельно.
8. На машине только Windows PowerShell 5.1 (pwsh 7 нет). Он читает `.ps1` без BOM как ANSI и ломается на кириллице. Поэтому любой `.ps1` с не-ASCII символами сохранять в **UTF-8 с BOM**. 18.11 BOM добавлен в `build_assembly.ps1`, `test_component.ps1`, `test_bubbles.ps1`, `test_ingame_localization.ps1`; после этого `test_component.ps1 -Component Outposts -CompileProbeOnly -UseBuiltAssembly` проходит.

## Обычный цикл функции

1. Claude: короткий TASK.md, сразу цепочкой `implement` → `integrate` → `run` (через `afterTask`) для Gemini.
2. Gemini: кандидат + самоаудит → `done`.
3. Claude: смотрит REPORT и «Куда смотреть Claude», при необходимости — конкретные строки diff. Одобряет или пишет короткий список правок (новая задача `implement`).
4. Gemini: `integrate` в корень, затем `run` — сборка, fresh и reload в игре, документация результата.
5. Claude: сверяет поля Result.json. Чисто — задача `accept`:
   - обычные функции, UI, тексты, ассеты, генерация карт → `accept` для Gemini (локальный коммит);
   - опасные зоны (пешки/WorldPawns, Scribe/сохранения, Harmony, платежи и поставки аванпостов) → `accept` для Codex.
6. Провал: Claude решает, исправлять или откатывать конкретные файлы через `git checkout`; исполняет Gemini.

Пока изменённый корень не принят, в `Assemblies/` может лежать непринятая DLL. Перед своей игрой пользователю стоит спросить Claude, что сейчас установлено.

## Hydrogen: обычный чат или Canvas (совет Hydrogen, 19.11)
- **Обычный чат** — когда нужно несколько отдельных файлов за один ответ, например 3–6 XML с путём над каждым блоком.
- **Canvas** — когда нужен один большой живой документ, который будем дорабатывать по частям: большой JSON (дизайн, таблицы квестов, баланс), длинный C#-файл, крупный XML на 500+ строк.
- Промпт под Canvas просит **ровно один артефакт** в нужном формате, без текста вокруг. Доработку формулируем как точечную правку: «обнови в документе только блок Института и добавь 2 флага в конец». Так Hydrogen меняет фрагмент на месте и не переписывает файл.
- В начале каждого промпта Claude пишет, в каком режиме его отправлять.
