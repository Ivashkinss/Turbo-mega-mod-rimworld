# GuestHemogenCountCases
Механическая подготовка 16 независимых контрольных примеров функции Wanted(value,max,gain) из Tools/Build/GuestHemogenCasesSnapshot/GuestHemogen.cs. Только результаты Tools/Build/GeminiGuestHemogenCountCases/: CASES.json, validate.py, REPORT.md. Код/игру/Git/Defs/настройки не менять, без сети.
Использовать IEEE754 float32: входы округлены в float32, затем отдельное округление после вычитания и деления, затем floor. Это не десятичная арифметика! Напр. границы value=0.6/0.8 при max=1, gain=0.2 надо вычислить, не угадывать.
Ровно16 кейсов с id, value,max,gain (числа или строки NaN/Infinity), expectedWanted, explanation. Набор: value0/0.1/0.2/0.4/0.5/0.6/0.8/0.9/1 при max1 gain0.2 (9 кейсов); отрицательное value; gain0; gain<0; valueNaN; maxInfinity; gainInfinity; переполнение положительного деления (max3.4028235e38,gain1.401298464e-45,value0) с ожидаемым clamp int.MaxValue. JSON должен быть стандартным (NaN/Infinity строками).
validate.py: независимый float32 расчёт через struct, проверка16кейсов +4 отрицательные мутации (десятичный floor на границе, округление вверх, разрешение gain0, потеря clamp). Не запускать сборки игры. Отчёт до70 строк, ясно: проверяется только арифметика количества, не решение о необходимости/цене/покупке. Codex сам проверит эти данные на настоящем C# в игре.
