# Реестр именных героев — проект (Claude, 18.11.2026)

Основа для всех 15 фракций. Источники:
- `Documentation/FACTIONS-CONTENT-PLAN.md`: ранги, герои и решения пользователя от 18.11;
- каталог `Tools/Build/GeminiFactionContentRegistry/CHARACTERS.json`: 84 героя, принят.

## Цель
Каждый именной герой существует в мире **в одном экземпляре**: у него постоянный ID, одна настоящая пешка (или особое представление) и понятное состояние. Генерация базы, рейда или квеста не клонирует героя и не воскрешает погибшего.

## Данные
`HeroDef` (Def, XML) — неизменяемое описание:
- `defName` = ID каталога, например `TMM_Hero_preston_garvey`;
- `faction` → FactionDef; `rank` 1–4; `isLeader`, `councilMember`;
- `representation`: `HumanlikePawn` | `AiTerminal` | `Robot` | `Giant` (последние три — позже, отдельными задачами);
- `pawnKind`, имя (`nameFirst`, `nameNick`, `nameLast`), пол, возрастной диапазон, `forcedTraits`, `skills` (минимумы), `apparel` и `weapon` (списки ThingDef, только существующие);
- `uniqueWeaponOneShot` (bool) — для клинков из решения пользователя, без этой фазы — false.

`HeroRegistry : WorldComponent` — изменяемое состояние, `Scribe`:
- `Dictionary<string defName, HeroRecord>`;
- `HeroRecord`:
  - `state`: `Unspawned` | `AtHome` | `Away` | `Captive` | `Dead` | `Joined` | `Missing`;
  - `pawn` — `Scribe_References`; пешка лежит в WorldPawns как `KeepForever`, пока она жива и не на карте;
  - `homeSettlement` — `Scribe_References` на Settlement;
  - `deathTick`, `successorOf`.

## Правила
1. **Создание лениво.** Пешка создаётся при первом запросе `HeroRegistry.GetOrCreate(heroDef)`, по `HeroDef`. Повторный вызов возвращает ту же пешку. Если герой `Dead`, вызов возвращает null и не создаёт новую пешку.
2. **Отслеживание.** Смерть, пленение, присоединение к игроку и уничтожение отслеживаются Harmony-постфиксами на `Pawn.Kill`, `Pawn.SetFaction`, `Pawn.Destroy`, а также по `Pawn.Discard`. В WorldPawns герою всегда ставится `KeepForever`, чтобы GC его не стёр.
3. **Генерация не клонирует.** Генераторы базы, рейдов и квестов при выборе состава сначала спрашивают реестр. Герой, который `Away` или `Captive` у игрока, не появляется на своей базе.
4. **Лидер.** Лидер фракции — `faction.leader` = пешка героя с `isLeader`. Если лидер погиб, лидером назначается следующий по `successorOf`, а без него — рангом ниже. Если погиб последний кандидат, используется ванильный выбор лидера. Совет (Волт-Тек) — это несколько `councilMember`; формальный ванильный лидер — первый живой член совета.
5. **Старые миры.** При загрузке сейва без реестра он создаётся пустым. Существующих пешек реестр не трогает и задним числом не пересоздаёт.
6. **Без фракции.** Если FactionDef героя нет в мире, `GetOrCreate` возвращает null без исключений.

## Этап 1 (первая задача реализации)
- `HeroDef`, `HeroRegistry`, правила 1–6.
- XML 3 героев Охотников и Минитменов: Престон Гарви (лидер), Дин и Сэм Винчестеры. Фракцию — из прототипа после `MinutemenRebaseRun`; если её нет, временно привязать к ванильной OutlanderCivil только в тесте.
- Probe:
  - `GetOrCreate` дважды → одна пешка;
  - смерть → `Dead`, `GetOrCreate` → null;
  - reload → то же состояние и ссылки;
  - лидер погиб → преемник;
  - GC WorldPawns не стёр героя: 2 дня реальных тиков;
  - `runtimeErrors = 0`, `unresolvedReferences = 0`.
- Генераторы баз и рейдов не трогать — это этап 2.

## Не входит
Внешность гигантов и роботов, ИИ-терминал Эдема, легендарные награды, квесты, оружие с одним ударом, бура против Дика Романа.
