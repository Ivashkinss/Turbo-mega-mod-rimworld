# Turbo mega mod

Объединение выбранных модов и русификация для RimWorld 1.6/1.7. Технический packageId: `colonyproject.integrated`.

## Что уже включено

- 27 зданий Neat Storage с удвоенной вместимостью.
- 7 холодильников [sbz] Fridge с исходной вместимостью.
- Smart Speed (четвёртая скорость и управление замедлением) и Smarter Construction (выбор порядка строительства). Они загружаются из Components, когда оригиналы отключены; при включённых оригиналах встроенные DLL пропускаются. Копия старой Harmony из Smart Speed не включена.
- Адаптивная сетка предметов в большом холодильнике; код раскладки не менялся в текущем этапе.
- 1239 уникальных русских записей: хранилища, Adaptive Storage, 615 восстановленных строк Dev In Your Language, локализация Melee Animation и Dynamic Trade Interface.
- Для анимаций и торговли: 319 исходных ключей Keyed, 137 полей определений, 8 пакетов с 45 строками боевого журнала, 10 строк интерфейса внутри DLL (включая название настроек Smart Speed) и 3 названия режимов смещения тел.
- На RimWorld 1.7 список участников дружеских поединков Melee Animation собирается в основном потоке перед параллельной обработкой. Это устраняет воспроизведённую ошибку `MapPawns.AssertMainThread`, сохраняя исходные условия участия.

Melee Animation и Dynamic Trade Interface остаются внешними модами: здесь добавлен их перевод. Сейчас объединены Neat Storage, Fridge, Smart Speed и Smarter Construction — 4 из 28 запланированных компонентов. Camera+ исключён по просьбе пользователя.

Дополнительно переведены 16 ключей Smart Speed и 21 строка окна добавления фракций VEF. Код VEF пока остаётся внешним.

## Установка и порядок

Папка с About/About.xml должна лежать непосредственно в Mods. Для работы нужны Harmony и Adaptive Storage Framework. На 1.7 нужна Harmony с поддержкой .NET 10: проверена версия мода Harmony 3.0.2.0 с библиотекой Harmony 3.0.0-rc.5. Устаревшая Harmony 2.3.6 выдавала `CoreCLR version 10.0.15 is not supported`.

Оставьте Melee Animation, Dynamic Trade Interface и Dev In Your Language включёнными, чтобы пользоваться их механиками и переводом. Поставьте Turbo mega mod ниже этих компонентов и Adaptive Storage. Исходные Neat Storage и [sbz] Fridge не нужны: их содержимое уже включено. Не включайте их одновременно с Turbo mega mod.

После обновления DLL перезапустите игру. Существующие вручную заданные лимиты отдельных хранилищ сохраняются в сохранении; повышайте их через настройки самой постройки при необходимости.

## Проверки и ограничения

- 18 проверок с настоящей Harmony: форматирование, ветвления, три значения перечисления, вложенный итератор, реальное имя класса настроек, разметка, воспроизведение и устранение ошибки фонового перечисления.
- Статически проверены параметры, грамматические токены и префиксы правил, вложенность тегов и переносы строк. Дубликатов русских ключей нет.
- Внутри RimWorld 1.7.5000 автоматически сверяются 1006 ключей, 225 полей и 45 строк грамматики, установка семи перехватов, русское название настроек торговли, разметка и три значения перечисления.
- Хранилища проверяются и без удалённых оригиналов: по исходным вместимостям в StorageChanges.json, XML из сохранённого коммита и хешам 240 графических ресурсов. Исторические 720 проверок раскладки относятся к неизменённому коду холодильника.
- Текущие результаты находятся в Documentation/LocalizationCheckpoint.json, RuntimeLocalizationTests.json, Verification.json и InGameLocalization.json. Успешная сверка данных не заменяет визуальный осмотр настроек, торговли, боевого журнала и изображения холодильника.
- В установленной игре есть посторонние ошибки русификации: повреждённый Actions.xml исходного Dev In Your Language, устаревшие поля перевода Core/DLC и неверное правило названия фракции в русском переводе Odyssey. Они отмечены отдельно; игровые файлы и исходный Dev In Your Language не изменялись.

## Разработка

Все изменения проекта — внутри этой папки. Сохранения, настройки и журналы тестов не коммитятся. Завершённые проверенные правки отправляются в https://github.com/Ivashkinss/Turbo-mega-mod-rimworld.

Python 3 с lxml:

```text
python Tools/fetch_build_references.py
python Tools/verify_combat_localization.py
python Tools/verify_storage.py
python Tools/verify_utility_components.py
```

В PowerShell:

```powershell
./Tools/build_assembly.ps1
./Tools/test_runtime_localization.ps1
./Tools/test_ingame_localization.ps1 -ObserveSeconds 60
```

Сборка сохраняет совместимость с ABI 1.6. На компьютере с 1.7 используются только для компиляции закреплённые reference assemblies Krafs.Rimworld.Ref 1.6.4871; загрузчик проверяет SHA-256 пакета. Можно передать `-ManagedPath` с библиотеками установленной 1.6. Сборки Harmony и Adaptive Storage берутся из соседних папок модов; DLL этих зависимостей в проект не копируются.

Игровой тест требует закрытой RimWorld. Он создаёт отдельный профиль в игнорируемой TestRuns, временно добавляет тестовую DLL, запускает новую быструю колонию и удаляет тестовую DLL после завершения. Пользовательский профиль не меняется. Проверка отдельно отмечает точную пару ошибок дефектного русского правила Odyssey; прочие ошибки завершают тест с неуспехом.

Tools/build_storage.py и другие инструменты повторного импорта требуют оригинальных ресурсов и не нужны для обычной проверки или запуска готового мода. Их нельзя запускать после удаления оригиналов, не восстановив источники.

## Вылеты 1.7 и проверка рендеринга

На этой машине GPU-вылет VK_ERROR_DEVICE_LOST воспроизводился добавлением одной Camera+ к рабочей основе. По просьбе пользователя Camera+ удалена и исключена из плана; её запись удалена из активного списка с резервной копией. Новая карта с полным оставшимся набором и копия пользовательского сохранения после удаления Camera+ загружаются и отрисовываются без этого вылета в проведённых проверках. Это не гарантия всех игровых сценариев и конфигураций.

Первое наблюдение «процесс прожил до таймера» было недостаточным. Теперь отдельно фиксируются появление карты, число кадров и игровые тики. Копия старого сохранения может быть на паузе из-за окна добавления фракций VEF: нулевые тики при работающем рендеринге явно отмечаются. Результаты — Documentation/CrashInvestigation.json.

MapPreview.TrueTerrainColors занимал 42,7 секунды при создании кэша в новом тестовом профиле. В обычном профиле кэш уже был. Для сопоставимых тестов готовый TrueTerrainColorsCache.xml и настройки модов копируются в тестовый профиль; это устраняет именно повторную подготовку кэша, а не меняет код Map Preview.

Повторяемая проверка с настоящим рендерингом:

```powershell
./Tools/test_rendering.ps1 -ObserveSeconds 120
# Для проверки сохранения передать -UseSavedCopy -SaveFile с путём к .rws.
```

Этот тест открывает окно игры, использует отдельный профиль и временную DLL, затем намеренно закрывает процесс по таймеру и удаляет тестовую DLL. Оригинальное сохранение не изменяется. В старом сохранении могут остаться записи CameraPlus.CameraSettings и CameraPlus.SavedViews: движок сообщает об отсутствующих классах; в проверенной копии это не мешало загрузке карты. Исходный файл сохранения вручную не редактировался. Также остаётся отдельная ошибка инициализатора кеша VEF на 1.7; её не следует смешивать с воспроизведённым GPU-вылетом Camera+.
